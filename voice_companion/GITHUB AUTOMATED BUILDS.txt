GITHUB AUTOMATED INSTALLER BUILDS

The source folder voice_companion and the .github folder must both be placed at the root of willwalsh14-hub/voice-companion-updates. Keep .github/workflows/windows-installer.yml in that exact location. GitHub does not run a workflow stored only inside a ZIP or a release attachment.

On GitHub, open the repository, then Actions, then Build and publish Windows installer, then Run workflow. The Windows build installs its tools, generates every manual, runs the release tests, packages the models and speech engines, creates Setup, and silently installs and checks it on the GitHub computer. Only after those checks pass does it publish the installer and update feed. It uses GitHub's temporary repository token, so no browser sign-in or personal access token is needed during a build.

The run must be in the updates repository because the existing update feed points there. Source uploaded to a different repository needs separate permission to publish to the updates repository.

A failed run does not announce a successful update. Its build and publishing logs remain available in the Actions run for seven days. Updates committed to the source folder or the Windows build workflow on main automatically start a build. Run workflow remains available for manual retries. Only a passing build is published.

Do not upload your personal app settings, email tokens, passwords, AI API key, local user data, or build logs with the source. The distributor's Microsoft desktop registration is a public client ID. If Gmail requires a distributor registration, provide the intended Desktop OAuth registration through a repository secret rather than committing a personal credentials file.

GitHub has no speaker playback device. Unattended builds generate and validate Windows speech audio in a WAV file and exercise pause, resume, and purge calls. Audible speaker playback and microphone timing still require testing on a local Windows computer. Local builds retain the speaker playback and speech interruption checks. The local installer builder continues to work normally; its Unattended option is for the automated Windows build.
